1. Purpose 
The purpose of this document is to show the data required when learner results are assessed and moderated and 
subsequently a Statement of Result is generated. 
 
2. In Scope 
This document will aim to show the following: 
 The data associated with a learner application include the following critical data entities: 
o Primary Data 
 Learner 
 Provider 
 Employer  
 Learning Programmes 
o Referenced Data -Reporting 
SETMIS 
 Learners who have completed the learning programmes 
 Learners who have not yet completed the learning programmes 
NLRD 
 https://www.saqa.org.za/documents/nlrd-documents 
 Please see referenced documents on annexure 7.1

Table 2: List of Definitions 
Term Definition 
Actor 
An actor specifies a role played by a user or any other system that interacts 
with the subject." 
Business Rule A statement expressing a policy or condition that governs business actions 
and establishes data integrity guidelines 
Candidacy 
A period of workplace-based learning undertaken by a graduate as part of 
the requirement for registration as a professional in the required professional 
designation as stipulated by a professional body. 
Data The reinterpretable representation of facts or figures in a formalised manner 
suitable for communication, interpretation, or processing. 
Economic Status ID This procedure means employed person registering for a learnership.  
Employed Learner A permanently employed learner registering for learnership. 
Enrolled Has same reference as Registered (Approved by merSETA).  
Information 
All data presented in a context so that it can be applied or used, records and 
knowledge in electronic or any other format, which forms part of the 
intellectual capital used, transformed, or produced by the organisation 
Review 
The process of establishing the compliance, accuracy, and completeness of 
the submission for merSETA to consider registration of recruited and 
selected learner/s. 
Rejection 
The act of not accepting the application to register a learner as the 
requirements for registration based on verification of submitted learner data 
and records for compliance, accuracy and completeness has not been met. 
Role A defined action to be performed by a project team member 
Registered 
Means the merSETA has officially recorded a learner after it was able to 
verify compliance, accuracy, and completeness of information on the 
agreement and supporting documents that it met the set-out requirements 
Submission 
The action of presenting a document to the merSETA for consideration in 
any training intervention including but not limited to learner registrations, 
continuations, completions, assessments, moderation, and trade testing 
either in an electronic format or hard copy 
Unstructured Data 
Unstructured data is information that either does not have a predefined data 
model or is not organised in a pre-defined manner. Unstructured information 
is typically text-heavy, but may contain data such as dates, numbers, and 
facts as well.

5. Assessment and Moderation Business Rules  
Use Case Business Rules 
Login to the NSDMS  System must allow for the user to immediately be able to login on to the 
system after a successful approval by merSETA. Users who have a valid 
login id and password can only login into respective accounts 
Capture Assessed 
Summative Assessments 
Results 
 Assessor –Assessor must be registered against the programme that they 
are assessing. All assessors linked to a particular qualification; as well as 
unit standards must be displayed on the dropdown selection. 
 For progress moderation - the user should capture a minimum 50% of 
learning programme needs to be completed (Minimum credits required for 
the programme divided by 2) 
 MerSETA employer and is MerSETA funded the provider should have the 
ability to capture the progress and completion 
 MerSETA employer that is not funded the 50% rule is not required but the 
provider can capture progress of the learner. Providers can request for 
external moderation regardless of the 50 percent rule 
 The capturing of assessments should be done for registered, recorded and 
expired learners  
 Grey out the unit standards that have been upheld AS COMPETENT 
(verification of moderation) to ensure no duplicate US get sent for 
Verification more than twice - Progress capturing 
 When a learner is deemed competent for certain Unit standards from 
another learning programme however the learner is registering for another 
learning programme that has the same unit standards that they are 
deemed competent for those US should be greyed out as well

 If accreditation ends but the assessment was done prior to the end date 
the system should allow the user to capture the assessment, and not allow 
them to capture dates after the accreditation had expired 
 If a learner has not met the minimum required credits there should be a 
flag to the capturer indicating the message "are you sure you want to 
proceed" (Completion) 
 The system should pre-populate a Yes on the report if credit compliance is 
met and a No if credits compliance is not met irrespective of progress or 
completion. 
 The system should not allow any assessment date that falls outside the 
registration period of the Assessor 
Elective Unit Standards  Provider can increase the credits bearing of a qualification. 
 Credits- Qualification - everything must be populated, for learning 
programmes the unit standards for the learning programme should be 
populated (Cores, Fundamentals, Electives (Electives that are relevant to 
the specific learning programme)) 
 The calculation of the minimum required credits does not include non-
mandatory electives 
 The non-mandatory electives should be flagged 
Internal Moderation  Moderators cannot moderate the results that they have assessed. 
 Provision to capture multiple internal moderators and the list should be 
filtered to the names selected during the capture of the credits 
 Batch moderation page after completion of capture of the Assessments 
should be filtered by qualification 
 The user should be able to search and select learners per qualification for 
batching 
 The system should not allow a moderation date that falls outside the 
registration period of the moderator 
Verification of 
assessments (External 
Moderation) 
 Sample size Rules: 
- Selection should be a minimum of 10% of the batch of learners yet the 
user should also have the option to capture 30% either 50% or 100% of the 
batch learners 
- For the capturing of the sample size the system should auto select of the 
sample of learners based on the % of the sample size 
 Verification pool (External Moderation) should stay open until the site visit 
is scheduled by QA 
 The user should be able to change the scheduled date of the site and add 
a comment 
 Upon the generating the external moderation report should populate 
whether the SOR should be issued and if the certificates should also be 
issued 
 The report that’s being generated: the information will be sourced from the 
below information and be pre-populated on the report 
System Generated 
-    The Batch number 
-    The employer (Provider) accreditation number, name 
-    The assessors’ and moderators’ name 
-    The QA's name,

- Full achievement

ability to print their own SORs
